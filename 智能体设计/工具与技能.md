# 工具与技能

模型不碰磁盘、不发网络包、不驱动设备。它在一轮里只能做两件事：给出文字，或者点名一个宿主已经允许的动作。动作分两类：**工具**是宿主立刻能执行的能力；**技能**是教模型何时、按什么步骤去使用这些工具的说明。技能不是另一个进程，也不是一套新的插件运行时。

## 工具

工具由宿主注册：名字、参数格式、一段给模型看的短说明。模型返回调用请求后，宿主校验参数、执行、把一段短结果送回模型。结果要短：成功或失败、关键标识、下一步需要的几行内容。完整日志留在宿主侧。

个人助手里常见的工具：

| 工具 | 说明 |
| --- | --- |
| 文件读写 | 读、写、修改工作区文件，按名字搜索文件内容 |
| 执行命令 | 在工作区里执行命令 |
| 搜索抓取 | 搜索和抓取网页 |
| 发消息 | 给当前用户发一条消息 |
| 定时任务 | 登记、列出、暂停、恢复、取消；登记只写持久存储，到点执行的是调度器 |

接待和设备场景里还有另一类工具：表情、肢体、点单、下发一张图片。它们同样由宿主执行；模型输出的是标签或一份结构化决定，通道负责真正驱动设备。

工具名单在一轮开始时固定，模型不能在对话中安装新工具。需要新能力时，先在宿主里实现并加入允许名单，再让模型看得到。

有的运行时把发消息和任务登记做成模型可调用的外部工具，把文件和命令留给运行时自带的工具。两条路的分界相同：凡是要改变通道、日程或磁盘的事，都经过宿主的一次执行，模型只拿到执行后的文本。

## 技能

工具说明怎么用，往往比工具本身更长。如果把每个技能的步骤都放进系统提示词，每一轮都在重复发送用不上的规程，模型也更容易拿错步骤。

一份技能是一个目录，至少有一份说明：开头写名称和什么情况下应该使用，后面才是步骤、示例、可以调用的脚本路径。运行时在一轮开始时只把名称和适用时机放进上下文，并写明：判断用得上时，再用读文件的工具去读正文和同目录的其他文件。

模型的路径：

1. 从索引里看出「做某件事」有一份技能；
2. 读那份说明；
3. 按说明调用已经存在的工具。

技能目录必须在这一轮的工作目录下面，否则模型看不见索引。换一套模型运行时，技能文件可以保持不变，只换「如何发现这个目录」的方式。

技能里需要本地程序时，正文写明调用工作区里的哪个脚本，由命令工具执行。不在技能里再启动一个长期服务，也不把技能做成需要单独安装的插件。

## 领域技能

有些能力比一份说明更重：点单、迎宾、按资料回答问题，都需要专用的处理步骤和一大份资料。这种技能注册成一组专用节点，外加一份可检索的资料库。资料按条目存放，并有一份索引；节点在本轮问题到来时检索，只把命中的条目放进这个节点的提示，手册全文不进入系统提示词，也不进入其他节点。

两种技能是同一原则的两种做法——步骤和资料留在外部，这一轮只拿用得上的那一截：

| 维度 | 普通技能 | 领域技能 |
| --- | --- | --- |
| 检索执行者 | 模型自己读说明 | 节点内部，由运行时完成 |
| 资料形态 | 说明文件 | 条目化资料库 + 索引 |
| 模型职责 | 判断时机、读正文、调工具 | 决定怎么说、怎么用条目，不负责翻完整本手册 |

规划节点如果存在，它只决定「要不要走进这个领域技能」，不读取资料正文。资料出现在执行该技能的那个节点里。

## 权限

工具让模型能够改文件、跑命令、对用户发消息。边界要放在宿主，不能放在提示词的劝告里。

| 边界 | 规则 |
| --- | --- |
| 触发权 | 只有有权的人能触发一轮工作：个人助手里是主人；接待设备上是已登记的那条连接 |
| 工作区 | 命令和文件限制在这块磁盘上的工作目录，技能索引也从这里发现；不堆放无关大文件，避免被整段拉进上下文 |
| 名单 | 允许名单之外的工具调用直接拒绝 |
| 投递 | 模型调发消息工具只表示「请把这段文字发给本轮所属的会话」，指定不了另一个通道的内部对象 |
| 场景 | 共享场合不加载只属于某一个人的技能资料，由场景注册表决定这一轮能看见哪些技能 |

提示词可以提醒模型谨慎使用命令。真正挡住越权的是名单、目录和工作区，不是提醒本身。
