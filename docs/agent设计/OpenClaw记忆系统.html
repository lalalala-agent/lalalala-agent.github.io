记忆系统 ​

面向开源开发者的技术文档。描述 Agent 框架如何在模型外面保管记忆，按需取出少量内容放进提示。

本文聚焦记忆的分层、读写、检索与隔离，提示词装配规则另有专文。

一、为什么需要记忆系统 ​

模型的上下文窗口会在一轮结束后丢掉，也会在对话变长时装不下更早的内容。

记忆系统的设计目标：

  • 让 Agent 记住跨会话的事实、偏好、约定
  • 在有限的窗口里只放当前这一步要用的内容
  • 按范围隔离，不靠提示词提醒模型「请勿泄露」

核心原则： 记忆放在模型外面，由运行时保管。模型负责决定「要不要查、查到的内容怎么用」；运行时负责保存、过期、检索，并且只把查到的那几条交回去。

二、分层架构 ​

2.1 三层模型（通用对话系统） ​

最常见的分层来自认知科学类比。三层对应三种寿命，往上越接近模型，越短、越完整；往下越适合跨会话，越只留值得记住的事实。

层存放内容寿命与迁出
工作记忆进程内最近若干轮的原文，供紧接着的下一句使用有轮次上限，超限的轮次被挤出，进缓冲或压缩成更短记录
短期缓冲进程外缓存，按用户和设备分开挤出的轮次、一段时间积累的对话轮次达上限或距上次写入超时，满足任一即迁出
长期事实持久存储，按用户+智能体标识偏好、决定、稳定情况、未完成的约定按当前问题检索，返回少数几条相关事实

三层的方向是单向提升：原文先留在工作记忆，挤出后进缓冲，缓冲再被抽取成事实。事实不会反向写成完整对话。

2.2 文件式做法（OpenClaw 风格） ​

同一件事也可以不经过向量库，而放在工作区的文件里。适合单用户、由智能体自己维护笔记的场合。

材料内容更新方式
长期偏好（USER.md）已确认的偏好和重要事实；稳定、短、允许被修订智能体用写文件工具更新，人也可以直接改
长期记忆（MEMORY.md）整理后的持久事实、决定、约定人工维护或自动整合
会话原文按日期归档，一天一个文件由运行时在每一轮结束后追加

USER.md 与 MEMORY.md 分开的原因： 偏好遵循和事实回忆的失败模式不同。偏好需要在查询附近重述才有效；事实可以按相关性检索。

USER.md 的格式契约：

  • 条目是祈使指令：「总是」「从不」「偏好」，不是「用户曾经说过」
  • 每条带状态元数据：观察日期、活跃或已替代
  • 更新就地替代：偏好改变时重写指令，不追加矛盾条目

2.3 两种做法对比 ​

维度三层模型文件式做法
工作记忆内存或缓存进程内，有轮次上限
情景记忆文档数据库，精确匹配按日期归档文件，搜索 + 切片
语义记忆向量数据库，相似性搜索向量库 + 精选文件
用户模型存在语义记忆中单独 USER.md，祈使指令

三、读写规则 ​

3.1 一轮结束时写什么 ​

运行时把这一轮追加到工作记忆，并按规则考虑是否迁出。长期事实的写入看价值，不看字数：

值得留下不写入
用户明确表达的偏好和限制寒暄、重复的确认
已经做出的决定只在这一分钟成立的状态
还没做完的约定模型自己的推测（要留，须在后续对话里被用户确认后再写入）
以后换一天仍然成立的事实—

定时任务和心跳使用独立的短会话，它们的提示和回复不追加进日常聊天档案。否则每小时一次的巡检会把日常记录冲满，检索时也会把巡检话术当成用户说过的话。

3.2 压缩前的自动刷新 ​

当会话接近自动压缩（compaction）阈值时，OpenClaw 触发一次静默的 Agent 轮次，提醒模型在上下文被摘要之前写入持久记忆。

  • 软阈值：会话 token 估算超过 contextWindow - reserveTokensFloor - softThresholdTokens 时触发
  • 静默：默认提示包含 NO_REPLY，用户看不到这一轮
  • 一次压缩周期一次：在 sessions.json 中跟踪
  • 需要写权限：沙箱只读模式下跳过

四、检索机制 ​

4.1 两条通道 ​

检索按成本分成两条通道：

通道机制模型调用
Lane 1（始终开启）Bootstrap 注入 + 排序搜索 + 触发词注入零模型调用
Lane 2（升级通道）真实子代理，可跨会话搜索和阅读仅在需要时运行

4.2 Lane 1 的三个机制 ​

Bootstrap 注入： MEMORY.md 和 USER.md 在会话开始时加载，每轮在预算内刷新。

排序搜索： 混合相关性 × 指数时间衰减（30 天半衰期）× 重要性乘数。重要性在写入时由模型分配，无需查询时调用。

触发词注入： 写入者可给条目附加触发短语。入站消息运行时快速词法和向量预过滤，匹配强的条目作为紧凑隐藏上下文块注入，每轮最多三条。自动注入仅限精选层——MEMORY.md 和 USER.md 的条目才有资格，日常笔记和转录永远不会自动注入。

4.3 Lane 2 的触发条件 ​

两个都满足才运行：

  1. 消息显示回忆意图：明确引用过去、时间措辞、直接询问先前决定或对话
  2. Lane 1 没有产生强命中

4.4 记忆读取工具 ​

在复杂 Agent 中，直接把记忆库全部塞进上下文会面临三个致命问题。解决方案是在 System Prompt 中制定规则：

在回答任何关于先前工作、决定、日期、人员、偏好或待办事项之前：先执行 memory_search；然后使用 memory_get 仅提取所需行。

工具作用
memory_search不读取全文，像搜索引擎一样，根据当前问题在记忆文件中找到相关片段/位置
memory_get读取特定的记忆文件，可以指定起始行和读取行数，只把真正需要的几行拉入当前上下文窗口

核心原则： 让大模型只负责「决策需要什么数据」，让外部工具负责「高效过滤和提取数据」。

五、短时模态 ​

情绪、画面、本轮临时事项，寿命比对话更短，不能写进长期事实。

模态存放规则
情绪按设备和用户存放最近几次判断，带过期时间连续几次接近，才把它当成当前情绪；过期后当作没有
画面只在感知通道里保留最近若干帧供需要看图的那一次使用；帧不进入对话原文
临时事项本轮抽出、预计很快过期的条目有条数上限和过期时间，到期删除

这些状态回答的是「现在怎样」；长期事实回答的是「这个人一直是怎样」。把情绪和画面写进长期库，下一周的对话会读到过期的现场。

六、范围隔离 ​

记忆按范围隔离。检索时带上范围，不靠提示词提醒模型「请勿泄露」：

范围规则
长期事实同时按用户和智能体过滤；一台设备上的对话默认不取另一台设备为同一人写下的记录
归档与工作记忆跟会话走；日常会话和某一次定时任务是不同会话
个人长期记忆只进入与该用户的直接会话；群聊、多人在场的共享场合不注入
短时模态键包含设备标识；设备断开或超时后，情绪和画面一并失效

七、核心原则总结 ​

原则说明
模型只决定查什么保存、过期、检索由运行时负责
三层单向提升工作记忆 → 短期缓冲 → 长期事实，事实不反向写成对话
写价值，不写字数偏好、决定、约定留下；寒暄、瞬时状态不留
两通道检索Lane 1 零模型调用，Lane 2 仅在回忆意图且无强命中时运行
自动注入仅限精选日常笔记和转录不自动注入，是安全属性不是调优
压缩前自动刷新接近窗口上限时静默提醒模型写入持久记忆
范围由运行时填写用户、会话、项目、设备四重隔离
短时模态不进长期库情绪、画面、临时事项有独立过期机制

八、一句话总结 ​

记忆放在模型外面，由运行时保管。三层模型（工作记忆 → 短期缓冲 → 长期事实）单向提升，事实不反向写成对话。文件式做法用精选的 USER.md 和 MEMORY.md 每轮直接可见，按日期归档的会话原文按需搜索和切片。检索分两通道——Lane 1 零模型调用（Bootstrap + 排序 + 触发词），Lane 2 子代理只在回忆意图且 Lane 1 无强命中时运行。自动注入仅限精选层，日常笔记和转录永远不会自动注入，这是安全属性不是调优选择。范围是查询参数，由运行时填写，不由模型在对话里改写。
