# RK3588 与 RK1828 硬件架构及 AI 计算平台入门

> 本文是 RK3588 AI 模型部署开源指南的第一篇，介绍硬件架构、AI 计算资源、软件生态及模型部署的基本概念，为后续大语言模型和视觉模型实战建立基础。

## 1. RK3588 与 RK1828 简介

RK3588 是一款集成 CPU、GPU、NPU 和多媒体处理能力的 SoC，适合运行 Linux、视觉算法及边缘 AI 应用。

RK1828 则是一款 AI 协处理器，可通过高速接口连接 RK3588 等主控平台，为系统扩展 AI 计算能力。它并不是 RK3588 的替代品，而是面向更高 AI 算力需求的扩展方案。


| 项目    | RK3588                        | RK1828            |
| ----- | ----------------------------- | ----------------- |
| 产品定位  | 主控 SoC                        | AI 协处理器           |
| CPU   | 4× Cortex-A76 + 4× Cortex-A55 | 三核 RISC-V 64 位处理器 |
| AI 算力 | NPU 标称 6 TOPS INT8            | 标称 20 TOPS INT8   |
| 内存    | 由开发板配置决定                      | 5 GB 片上堆叠 DRAM    |
| 主要用途  | 系统运行、视觉推理、应用调度                | 扩展 AI 推理能力        |
| 连接方式  | 系统主控                          | 可通过 PCIe 2.1 连接主控 |


以上 RK1828 规格参考 Firefly 公开的 AI 计算模块文档；具体产品形态和可用资源应以实际模块及开发板为准。

参考资料：[RK1828 AI 计算模块介绍](https://github.com/Firefly-docs/products-docs/blob/master/en/Accessories/RK1828/started.md)、[Rockchip RK3588 数据手册](https://www.rock-chips.com/uploads/pdf/2022.8.26/191/RK3588%20Brief%20Datasheet.pdf)。

## 2. RK3588 硬件架构

RK3588 的主要计算资源包括 CPU、GPU 和 NPU。

### 2.1 CPU

RK3588 采用八核 CPU 架构：

- 4 个 Cortex-A76 高性能核心。
- 4 个 Cortex-A55 高能效核心。

CPU 主要负责操作系统、业务逻辑、图像预处理、模型输入输出处理、网络通信及任务调度。

### 2.2 GPU

RK3588 集成 ARM Mali-G610 MC4 GPU，主要用于图形渲染及受相应驱动和框架支持的计算任务。

在 AI 应用中，GPU 可以承担图形界面、图像显示等工作，但不能直接将 GPU 与 NPU 视为同一种推理执行环境。

### 2.3 NPU

RK3588 集成三核 NPU，标称总 INT8 算力为 6 TOPS。

NPU 主要用于执行经过相应工具链转换、且算子和数据类型受到支持的神经网络模型，例如图像分类、目标检测和图像分割。

实际推理性能不仅取决于峰值算力，还受到模型结构、量化方式、内存访问、预处理及运行时调度影响。

## 3. RK1828 如何扩展 RK3588 的 AI 能力

在需要运行更大模型或增加 AI 任务吞吐量的场景下，可以考虑 RK3588 搭配 RK1828 的方案。

```text
┌─────────────────────────────────┐
│             RK3588              │
│                                 │
│ Linux / 应用程序 / 网络服务      │
│ CPU / GPU / 本地 NPU            │
└────────────────┬────────────────┘
                 │
              PCIe 2.1
                 │
┌────────────────▼────────────────┐
│             RK1828              │
│                                 │
│ AI 协处理器                     │
│ 20 TOPS INT8                    │
│ 5 GB 片上堆叠 DRAM              │
└─────────────────────────────────┘
```

典型分工如下：


| 任务            | 建议承担方             |
| ------------- | ----------------- |
| Linux 系统与业务应用 | RK3588            |
| 摄像头输入及应用逻辑    | RK3588            |
| 轻量级视觉模型       | 可先评估 RK3588 NPU   |
| 更高 AI 算力需求    | 评估 RK1828         |
| 大语言模型或视觉语言模型  | 根据模型、内存及工具链支持情况选择 |


RK1828 的公开产品资料提及 3B～7B 参数规模的 LLM/VLM 应用，但这不代表所有同等规模的模型都能直接部署。模型结构、量化方式、运行时版本和实际内存需求仍需逐项确认。

还需要注意，两个处理器的标称 TOPS 不能直接相加后当作单个模型的实际性能。主控和协处理器之间的通信、内存及软件调度都会影响最终表现。

参考资料：[Firefly RK1828 模块说明](https://github.com/Firefly-docs/products-docs/blob/master/en/Accessories/RK1828/started.md)。

## 4. AI 软件生态与工具链

在 RK3588 平台上部署 AI 模型，通常需要经过模型转换、量化、导出和板端推理几个阶段。

### 4.1 主要工具链


| 工具链                  | 主要用途         | 典型场景               |
| -------------------- | ------------ | ------------------ |
| RKNN-Toolkit2        | 模型转换、量化与验证   | RK3588 视觉模型        |
| RKNN Runtime / Lite2 | 板端模型推理       | 分类、检测、分割           |
| RKLLM-Toolkit        | 大语言模型转换与导出   | 支持的 LLM            |
| RKLLM Runtime        | 大语言模型板端推理    | 文本生成与问答            |
| RKNN3 工具链            | 新一代模型转换与运行生态 | 需根据具体硬件及协处理器支持情况选用 |


官方项目：

- [RKNN-Toolkit2](https://github.com/airockchip/rknn-toolkit2)
- [RKNN Runtime](https://github.com/airockchip/rknpu2)
- [RKLLM](https://github.com/airockchip/rknn-llm)
- [RKNN3 Toolkit](https://github.com/airockchip/rknn3-toolkit)
- [RKNN3 Model Zoo](https://github.com/airockchip/rknn3-model-zoo)

**工具链选择需要特别注意：** RKNN-Toolkit2 与 RKNN3 Toolkit 并不是可以直接互换的同一版本工具。RK3588 本地 NPU 部署和 RK3588 搭配 RK1828 的协处理器部署，也可能使用不同的模型格式、Runtime 和通信组件。应根据官方项目列出的支持平台选择正确方案。

## 5. AI 模型的基本部署流程

无论是视觉模型还是大语言模型，都可以按照以下思路理解部署过程：

```text
原始模型
   ↓
检查模型结构与硬件兼容性
   ↓
使用对应工具链转换和量化
   ↓
导出目标平台模型文件
   ↓
部署 Runtime 与模型
   ↓
加载模型并执行推理
   ↓
验证精度、速度和资源占用
```



### 5.1 视觉模型

视觉模型通常采用 RKNN 工具链，典型流程为：

```text
PyTorch / ONNX
      ↓
RKNN-Toolkit2
      ↓
量化与转换
      ↓
.rknn 模型
      ↓
RKNN Runtime
      ↓
RK3588 NPU 推理
```

入门时建议从图像分类模型开始，再逐步学习目标检测和图像分割。

### 5.2 大语言模型

大语言模型通常采用与模型和硬件版本匹配的 RKLLM 工具链，典型流程为：

```text
原始模型权重与 Tokenizer
          ↓
检查模型兼容性
          ↓
RKLLM-Toolkit
          ↓
量化与模型导出
          ↓
.rkllm 模型
          ↓
RKLLM Runtime
          ↓
Prompt 输入与文本生成
```

大语言模型部署还需要重点关注权重大小、量化精度、上下文长度、KV Cache、运行内存及生成速度。

如果目标是使用 RK1828 扩展大模型能力，应先确认该模块所配套的官方 SDK、Runtime 和模型示例，而不是直接将 RK3588 本地 NPU 的部署流程照搬到协处理器上。

## 6. 后续学习路线

建议按照以下顺序学习：

1. **环境准备：** 确认开发板型号、系统版本、驱动和工具链。
2. **视觉模型入门：** 完成一个分类模型的转换与板端推理。
3. **大语言模型部署：** 完成一个受支持的 LLM 的转换、量化及文本生成。
4. **性能测试：** 测量推理延迟、FPS、tokens/s 和内存占用。
5. **多模型协同：** 将视觉识别结果传给 LLM，构建自然语言分析应用。
6. **RK1828 扩展：** 在确认硬件、SDK 和 Runtime 兼容后，测试协处理器上的 AI 推理方案。
