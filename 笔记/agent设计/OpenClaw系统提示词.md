## OpenClaw 提示词工程：身份与系统提示词

> 来源：OpenClaw 官方文档与社区技术拆解。OpenClaw 是一个自托管 AI Agent 网关，将聊天应用（WhatsApp、Telegram、Discord 等）连接到可调用工具的编码智能体，其核心设计理念是“LLM 只负责决策，外部工具负责执行与过滤”。


### 一、核心定位

OpenClaw 的系统提示词不是运行时默认的一段固定文本，而是**每次智能体运行时动态构建**的结果。人格不在模型权重里——换一份提示词文件，同一个模型就换一种说话方式和行为底线。

**硬约束：短、稳定、每轮都在。** 身份层不是记忆库，也不是技能手册。写长了，模型会把操作细则当性格，把过期事实当人设。


### 二、身份材料：拆成四份文件

OpenClaw 将 Agent 的“自我说明”拆成工作区里的 Markdown 文件，每份只回答一个问题：

| 文件 | 回答 | 内容 |
| --- | --- | --- |
| **SOUL.md** | 你是什么样的人 | 性格、语气、沟通风格、行为底线。如“可以有自己的观点”“做那个你真正愿意与之交谈的助手” |
| **IDENTITY.md** | 你叫什么、扮演什么 | 名字、角色、语言、emoji 标识等基础身份 |
| **USER.md** | 你在帮谁 | 用户信息、偏好、背景 |
| **AGENTS.md** | 工作步骤 | 会话启动流程、记忆使用约定、安全红线、群聊行为规范 |

此外，**MEMORY.md** 存放长期事实与决策，**仅在主会话（与用户的直接私聊）中加载**，不在群聊等共享上下文注入。

**组装发生在运行时，不发生在模型内部。** 一轮开始时，运行时按当前场景读出这些文件，拼成身份段，再附上本轮工具名单。


### 三、组装结构：三层模型

OpenClaw 的系统提示词按三层组装：

```
Layer 1 · System Prompt 层（静态核心，每次必带）
角色定位 / 能力边界 / 安全规则 / 工具指令 / 格式约束 / 行为策略
                ↓
Layer 2 · Workspace 注入层（运行时读取文件）
SOUL.md / USER.md / MEMORY.md / AGENTS.md / TOOLS.md
                ↓
Layer 3 · 技能注入层（按需加载）
命中技能的 SKILL.md + 相关配置
```

**优先级规则：** SOUL.md 定义的风格可以覆盖 System Prompt 的默认语气，但 **System Prompt 里的安全规则不能被任何层覆盖**——这在设计层面写死。


### 四、按场景注册，不换进程

同一套运行时服务多种场景。每种场景注册两样东西：**一份身份 + 一张该场景允许的执行图**。

- 点单场景：有菜单角色和确认订单步骤，没有迎宾导览话术
- 迎宾场景：拿不到点单专用节点
- 人设文案、表情动作词表：跟场景走，不跟进程走

新增场景 = 新增一份注册，不是再部署一个进程。身份文件和图的节点名单一起注册，避免“提示词答应了做某件事，图里却没有对应节点”。


### 五、什么不该放进身份层

| 不该放 | 正确做法 |
| --- | --- |
| **整库记忆** | 身份段最多写一句“涉及既往事实先去检索”；检索结果由运行时注入 |
| **全部技能步骤** | 只留技能名、一句话适用时机、“用到时再读正文” |
| **领域手册** | 写“遇到这类问题去检索”，不粘贴全文 |

**该放的：换一轮也不会变的规则**——我是谁、在哪种场景、不能越过的线、去哪里取记忆和技能。


### 六、边界规则

**subagent 不能进一步调用 subagent。**


### 七、一句话

> System Prompt 是 OpenClaw Agent 的“出厂设置说明书”：组合身份、记忆、技能、行为规则，告诉它“你是谁、你能干什么、该怎么干”。人格来自 Markdown 文件，不是模型微调——没有秘密配方，只有精心设计的提示词在每条消息前注入系统提示词。
